# X Article Bridge

把本地写好的 Markdown 或 HTML 文章，连同图片一起送进已经打开的 X Article 草稿。

X Article Bridge 是“谁是专家”做给自己用的 Chrome 扩展。它解决的是 X Article 发布里最琐碎、也最容易出错的一段：文章在本地已经排好了，文字可以复制过去，图片却不会像微信公众号那样跟着一起上传。

## 它解决什么问题

很多人的工作流是：先在本地编辑器或 AI 生成的网页里准备文章，再把内容搬到 X Article。单纯复制文字通常不难，真正麻烦的是：

- 本地 Markdown 的图片是相对路径，逐张重新找文件很慢；
- 图片上传完成后容易全部落到文章末尾，还要手动拖回原来的段落；
- 封面图片和正文图片是两套入口，重复操作容易造成误上传；
- 重试时如果只是继续追加，文章会被重复写入。

这个扩展把这段“手工搬家”变成一次导入和一次发布前检查。

## 核心能力

- 支持 `.md`、`.html`、`.htm` 单文件导入；
- 可把文件直接拖到 X Article 正文编辑框，也可从 Chrome 侧边栏选择文件；
- Markdown 图片支持一次选择全部文件，或选择图片所在目录；
- 按文章中的相对路径匹配本地图片，缺图、重名和无法读取会在写入前提示；
- 图片逐张交给 X 自己的媒体入口上传，等 X 返回真实媒体结果后，放回原来的图片标记位置；
- 正文导入完成后，可从已上传正文图片中选择封面，也可另外上传一张封面；
- 每次导入替换当前正文，失败后可以直接重试，不会继续追加同一篇文章；
- 某张图片上传失败时，会保留已经成功的图片和当前正文，可直接点击“重试失败图片”继续，不必删除文章或重新导入；
- 已上传但位置尚未确认时，重试只确认和修复这张图片的位置，进度分别显示已上传数量和已确认位置数量；
- 每次导入生成独立占位标记，正文可以正常讨论 `XABIMG1` 等技术例子，不会被当成插图位置替换；
- 导入和重试前核对页面桥接版本与能力，必要时由扩展后台恢复当前文章的通信，避免旧页面处理器与新版正文脚本混用；
- 导入前检查 X 当前正文媒体数量上限；2026-10-15 实测配置为 25 个正文媒体项，封面另计，超限时先提示并保留当前草稿；
- 单张图片最多等待 120 秒；全部上传后还会等待 X 的正文更新稳定，避免最后一张图片迟到时被误报完成或在重试时重复上传；
- 只负责写入 X 草稿，不会替你点击 Publish。

## 最短使用路径

1. 在 Chrome 打开 `chrome://extensions`，开启“开发者模式”，选择“加载已解压的扩展程序”，指向本项目目录。
2. 登录 X，打开或新建一篇 X Article。
3. 将一份 `.md` 或 `.html` 文件拖进正文编辑框，或者点击扩展图标，在侧边栏选择文件导入。
4. 如果 Markdown 引用了本地图片，按提示选择全部图片，或选择包含这些图片的目录。浏览器只会把你明确选中的文件交给扩展。
5. 等待正文和图片处理完成。图片会回到原始标记所在的位置。
6. 如果某张图片失败，点击正文右上角或侧栏的“重试失败图片”；扩展会从失败处继续，已经成功的图片不会重复上传。
7. 需要封面时，点击侧栏的“单独设置封面”，从正文图片中选择，或另选一张本地图片上传。
8. 在 X 中检查标题、封面裁剪、图片位置和最终排版，再由你手动点击 Publish。

## 输入文件怎么准备

### Markdown

支持常见的一级至四级标题、段落、粗体、斜体、删除线、列表、引用、链接、代码和分隔线。第一个一级标题会作为 X Article 标题。

本地图片可以这样写：

```md
![示意图](./images/bridge.png)
```

导入时选择文件或目录后，扩展会根据这条路径匹配实际文件。文件名重复时需要选择更具体的目录，避免把错误图片上传到文章里。

### HTML

HTML 会保留 X Article 能识别的文章结构，例如标题、段落、列表、引用、链接和强调。完整网页的 CSS、脚本、交互组件和自定义布局不会原样搬进 X Article。

为了让 HTML 文件可以独立移动，图片优先使用 `data:image/...` 内嵌：

```html
<img src="data:image/png;base64,..." alt="示意图">
```

外部 URL 或相对路径图片会受到浏览器跨域、本地文件授权和 X 编辑器变化的影响；需要时可改用 Markdown 的本地文件选择流程。

## 重要边界

- 这是 Chrome MV3 扩展，当前适配 `x.com/compose/articles` 和 `twitter.com/compose/articles`。
- 需要登录 X，并且页面中必须已经打开或新建 X Article 编辑器。
- 扩展不调用 X 的发布 API，也不自动点击 Publish；最终发布权保留在你手里。
- X 的媒体格式、大小、上传接口和编辑器 DOM 可能变化。扩展会在找不到入口或上传失败时停止并提示，不会假装导入成功。
- 图片数量不是 5 张上限。扩展逐张上传，每篇正文当前按 X 的 25 个媒体项配置检查；单次媒体选择器最多 4 张与整篇文章上限是不同的约束。文章包含视频或 GIF 时也会占用正文媒体项。
- 图片超时后点击重试，会先继续确认上一项的上传结果；X 明确报上传失败时才重新发送文件。上传每张图片最多等待 120 秒，全部完成后还会检查最终正文状态。关闭或刷新页面会结束当前重试会话。
- 浏览器文件选择权限不能绕过。扩展只处理你主动选择的文件或目录，不会扫描整个电脑。
- 文章中的丰富网页视觉会被收敛到 X Article 支持的正文结构；封面裁剪仍由 X 完成。

## 目录说明

```text
manifest.json       Chrome MV3 清单
sidepanel.html/js   侧边栏导入与封面入口
src/                X 页面适配、格式解析、图片上传、封面处理
examples/            可直接试运行的 Markdown 与 HTML 样例
test/                格式、路径匹配、媒体完成和位置回写测试
docs/                设计说明、宣传稿与视觉素材
dist/                可直接分发的扩展压缩包
```

## 设计取舍

这个项目不试图把 X Article 变成另一个网页编辑器。它只做一件明确的事：把本地已经准备好的内容可靠地送进 X，并把图片和原文位置对应起来。这样写作、排版和图片制作仍然可以在熟悉的工具里完成，X 负责草稿、封面裁剪和最终发布。
