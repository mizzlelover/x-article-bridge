# 我给自己做了一个 X Article 发布插件

我以前觉得，发一篇 X Article，难的只是把文章写完。

后来才发现，真正磨人的，是最后那段“把内容送进去”的路。

正文还好办。把排好版的网页全选、复制、粘贴，标题、段落、粗体和列表大多能过去。我一度以为图片也会顺带进去，像微信公众号编辑器那样自动上传。

结果不是。

图片留在原页面，X Article 里只剩下文字。每一张图都得重新找文件、上传、再拖到对应段落附近。文章长一点，图多一点，最后这段手工活往往比写作本身更耗人。

我后来问 AI，也找过现成工具。确实有能把 Markdown 写进 X Article 的方案，但用下来总有几处不顺手：有的只接受 MD；有的本地图片要反复找目录、授权；有的需要先把文章建好，再按特定步骤操作；有的交互和我原本“文章、图片、排版都已经准备好”的工作流并不贴合。

于是我干脆给自己做了一个小插件：**X Article Bridge**。

![X Article Bridge：把本地稿件送入 X Article](assets/illustration_01_本地稿件进入X_v01.png)

它做的事很简单：把一份已经写好的 Markdown 或 HTML，送进正在打开的 X Article 草稿。

但我更在意最后那段原本最容易出错的流程。

比如 Markdown 里写的是相对图片路径，插件会让你一次选择全部图片，或者直接选择图片所在文件夹。它会按文章里的路径去匹配文件，缺图、重名或图片无法读取，会在写入正文前停下来说明白，而不是把错误的内容交给 X。

正文进入 X 后，图片不是一股脑堆在文章末尾。它会逐张走 X 自己的媒体入口上传，等 X 真正返回媒体结果，再放回原来那张图片标记所在的位置。

![图片上传完成后回到原来的段落位置](assets/illustration_02_图片准确归位_v01.png)

封面也单独处理：你可以从已经上传的正文图片里挑一张，也可以另外上传一张。封面裁剪和最终发布仍然留在 X 里完成。

这听起来并不是什么大功能，但做下来我才意识到：内容工具真正省下来的，不是“把一段文字变成另一段文字”，而是消掉那些每次都要做、每次都很容易错、又很难专注的最后一公里。

现在我自己就用它发 X Article。写作仍然在熟悉的编辑器里完成，图片也和文章放在一起；打开 X Article，导入，确认封面和排版，发布前再看一遍。流程终于从“手工搬家”变成了“交付前检查”。

![发布前只需完成最后检查](assets/illustration_03_发布前检查_v01.png)

它目前仍是一个围绕我自己工作流打磨的小工具，也不替你点击 Publish。X 的编辑器会变，实际发布前仍然应该看一眼草稿。但如果你也习惯先在本地写 Markdown，或者先用 AI 生成一份有图有排版的 HTML，再发布到 X Article，我想这个思路应该会有用。

我会继续把它整理好，也欢迎你告诉我：你在发 X Article 时，最烦的是哪一步？
